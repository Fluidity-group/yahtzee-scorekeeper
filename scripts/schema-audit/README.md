# Read-only migration baseline audit

This is the prerequisite audit requested before any Studio rollout migration or history repair. It does not apply SQL migrations, repair history, push a dry run or execute app/provider/cleanup routines.

- `catalog.sql` is a catalog-only SELECT inside `BEGIN ... READ ONLY` and `ROLLBACK`. It reports application table/column/constraint/index/trigger/policy metadata, explicit/effective ACLs, routine identity/security/configuration and definition fingerprints, project schema/publication membership and required extension metadata. Routine bodies and expressions/defaults are hashed, never returned. It never reads table contents, Vault secrets, storage object names or credentials.
- `operations.sql` reads only the two fixed migration-owned cron configurations and two fixed bucket configurations. Run it only after the catalog confirms those relations exist. Cron command text is hashed. It invokes no job, HTTP request or app function.
- The server administrator can expose a fixed `schema-audit --ref <committed-ref>` wrapper operation that runs these pinned files with `psql -X -qAt -v ON_ERROR_STOP=1 -f ...` and returns JSON. Do not add unrestricted SQL execution to the deployment wrapper just for this audit. The agent does not read admin credentials or edit the wrapper.
- `build-expected.mjs` applies the 16 migrations through202610240003 **only in disposable local PGlite**, with inert Supabase platform/extension boundaries. All application DDL, routine bodies, grants, policies and publication statements are unchanged. The pending Studio202610310001 migration is excluded. Artifacts are ignored under artifacts/sw078/schema-audit/.
- Each migration's source hash and cumulative changes are recorded. Compare the final state because later migrations deliberately replace earlier functions/constraints. PostgreSQL18 catalog-only NOT NULL constraints are omitted from the constraint group; column nullability is compared directly across versions. Server major differences still require review; default expression/canonical function formatting may differ and must not be waved through.
- `compare.mjs` fails closed on missing/extra/drifted objects, routine/ACL/RLS differences, missing extension/schema or incomplete/non-read-only snapshots. Even a full catalog match is not proof of historical execution, data backfills or permission to repair history. Repair is a separate Dan-approved administrator action.

Known non-schema effects to inspect separately: migration202610130001 backfills current/finished game snapshots and historyVersion;202610240001 creates the inert portrait-budget singleton and private portrait bucket;202610140007 creates the retention schedule;202610240002 creates a disabled hourly portrait-cleanup schedule;202610240003 creates the private animation bucket. Live budget/enablement and intentionally activated/paused schedules can be post-deployment operational settings, not missing-schema evidence. Never reset them to migration defaults or inspect/renew provider secrets/budgets to reconcile history.
