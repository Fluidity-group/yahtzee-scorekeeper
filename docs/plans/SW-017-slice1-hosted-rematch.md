## Root cause and implementation

Hosted and local finished Play again shared data-action=new; src/prototype.js reopened multiplayer entry for onlineRoom rather than issuing a successor operation. Server room held only one game; startRoom reused room UUID as game identity. Simply overwriting game would discard history. Preserved pre-fix worktree test reproduced openOnline call count2 instead of1; evidence artifacts/sw017-rematch/pre-fix-reproduction.log. This intentionally failing isolated test is outside the configured root suite. Fixed shared DOM tests demonstrate no second entry call.

src/multiplayer/rematch.js validates authenticated membership and exact finished game/revision, merges own readiness and allocates one successor after all players consent. Readiness is commutative across the same game revision; a result correction invalidates it. Successor keeps current game-time names/account seats/rules and chooses previous winner as startingSeat/activeSeat. Proposed tie fallback rotates to the next tied seat after prior starter; tie product policy remains reviewable before live use. Rematch deliberately limited to manual rooms; camera/BLE semantics unchanged.

New game IDs, gameSequence and gameId-bearing client commands prevent stale score submission into another game. Current game receipts remain bounded as before; readiness receipts are durable separately in the database, bound to actor and normalized payload. Historical snapshots are independently addressable instead of an unbounded room JSON. Migration backfills only genuine existing current games, not already-lost earlier games. historyVersion protects migrated first games too. SQL atomic commit locks expected room revision and writes prior/successor/room pointer/receipt together; conflicts roll back.

Server capabilities require the installed RPC. Realtime state preserves already-known capability metadata; foreground/poll reads remain existing recovery mechanism. Menu History for hosted games lists this table's saved games, and Export fetches paginated full snapshots plus current state. Account-wide stats/history projections and archived-score editing are later stages, not claimed in this slice. Current-game own-score correction remains supported.

The user-requested UI expert researched and implemented only new hosted-results module/style/test in isolated artifacts/sw017-ui-worktree. Root copied/integrated those files; agents did not concurrently edit root files. Existing celebrations remain based on newly accepted outcomes and stay quiet on reload/correction. Highlights derive from corrected final scorecards, not optional rolls/lifetime history. Nicknames remain frozen in each game; choosing a different next-game nickname is a later UI/domain feature. This slice does not add tournaments, manual combination reports, signup or Competition v2.
