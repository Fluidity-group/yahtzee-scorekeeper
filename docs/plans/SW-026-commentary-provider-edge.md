## Owned manifest and APIs

New `server/commentary/provider-runtime.js`, `scripts/build-commentary.mjs`, `tests/commentary-provider-runtime.test.js`, this plan. No production entrypoint is invented with an in-memory store: lead owns `server/commentary/edge.js` and its actual durable store/service/worker.

`createDurableProviderGate({verifyPersistence,readAllowance,reserveAttempt,finishAttempt})`: factory brand rejects arbitrary rehearsal objects or durable:true assertions. verifyPersistence() must verify an ACTUAL DurableCommentaryStore instance and backend readiness; factory itself does not establish persistence. Injecting callbacks that merely operate Maps would violate the composition contract, not transform Maps into durability. readAllowance(id) reads backend approved limits; reserveAttempt stamps the ALREADY submitted root attempt in the same durable CAS and returns matching committed receipt. It MUST NOT double-charge the service's existing reservation. No HTTP until receipt returned. finishAttempt persists sanitized token usage/status/latency/bytes, must be idempotent and avoid terminal state regression; unknown/cancelled cost remains counted and reconciled, no refund/retry inference.

Allowance record: {id,approved:true,revoked:false,expiresAt (server ms),maxWriterRequests,maxTtsRequests,maxTtsCharacters}. Runtime expected allowance uses identical fields except approval/revocation. Fresh read must match ID/expiry/caps exactly; missing/revoked/expired/altered allowance rejects. Root binds this record to actual clubhouse_commentary_limits scope/room/expiry. Root backend reserveAttempt must also enforce actual submittedCharacters and maxOutputTokens passed by writer, plus administrator model/provider limits. Local counters are conservative extra guards; database totals own restart/concurrent-worker accounting.

reserveAttempt input: {roomId,jobId,requestId,stage:'writer'|'tts',allowanceId,expiresAt,provider,model,submittedCharacters,maxOutputTokens?}; result {id:attemptUUID,allowanceId,requestId,stage,committed:true}. Root verifies matching committed submitted attempt/job/room and stamps providerDispatchedAt once before provider HTTP. requestId is the root persisted attempt ID, never arbitrary client text or a new retry identity. Writer callbacks adapt this verified receipt into existing Anthropic writer gate internal shape.
